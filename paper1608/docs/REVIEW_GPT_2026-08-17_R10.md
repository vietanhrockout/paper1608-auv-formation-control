## Findings

### [P1 visual] Desired/offset references become visually indistinguishable from the actual curves in Figs. 6–7

In Fig. 6, the dashed desired series is plotted first and the blue actual series is plotted afterward. Once tracking is close, the blue line covers the dashed line almost completely. The rendered figure therefore looks like a single blue curve over most of the horizon; the reader cannot visually distinguish “accurate overlap” from “reference not drawn.”

In Fig. 7, each target `yline` uses the same color as the corresponding actual curve. Once the actual curve lies on the target, the solid curve fills the gaps in the dashed target, so the converged portion again appears essentially solid.

Required presentation fix:

- draw desired/target references last (above actual data);
- use a neutral, high-contrast reference style (for example black/dark-gray dashed) or otherwise ensure the dash pattern remains visible under exact overlap;
- keep actual AUV/follower colors distinct;
- re-render and visually confirm that a reader can see both the reference and actual series throughout the tracked portion.

This is a presentation issue, not a numerical-data error.

### [P1 evidence] The `total_retracted` reconciliation is plausible but not independently auditable from the pushed repository

The inference is internally coherent: the committed 15 s and 100 s artifacts reportedly share the same cumulative count/max correction, while a surviving 90 s checkpoint has the same counter but a different actuator maximum, supporting a real counter freeze rather than a frozen checkpoint.

However, the key 90 s checkpoint is gitignored and exists only on Claude's machine, and no committed diagnostic script/output records the extracted fields and artifact hashes. A reviewer pulling the repository cannot reproduce the advertised three-point comparison.

Commit a small read-only reconciliation diagnostic and its text output containing, for each source artifact:

- artifact filename and SHA-256;
- simulated time / step count;
- `total_retracted` and `max_retraction` at full stored precision;
- `max_tau_act_moment` as the progressing control field;
- an explicit PASS/FAIL comparison.

The full 90 s checkpoint need not be committed. A durable, hashed extraction log is sufficient. Until then, phrase the reconciliation as locally verified evidence, not fully repository-reproducible evidence.

The Phase C “What this does and does not establish” paragraph still says the physical figures “can now be generated once the plotting pipeline is rewritten” and that `paper1608/plots/*.m` remains stale/guarded.
