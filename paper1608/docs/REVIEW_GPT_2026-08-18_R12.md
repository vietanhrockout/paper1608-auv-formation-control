## Findings

### [P1] `verify_step52_performance_criteria` is still a false oracle

Its header promises four performance checks, including steady-state checks
after 10 s and reaching before `T1*=5 s`, but the implementation runs only
`exp4_rl_pts_mc(0.5, ...)` and checks only saturation at the final sample. It
cannot possibly test criteria 1–3. Criterion 3 is also inconsistent with the
accepted Phase-C evidence: the literal 5 s reaching deadline was missed.

This is a latent verification defect missed by the claimed full-project audit.
Do not merely move this file between runner lists. Rewrite it as an
artifact-based oracle over the committed 100 s Phase-C result/analysis (or
retire it in favor of the existing Phase-C analyzer), with the currently
accepted criteria stated explicitly: the documented 10 s neighborhood and
full-tail boundedness, plus the separate force/moment actuator limits. It must
not call the known-stalling legacy `exp4_rl_pts_mc` path.

### [P1] The runner's single “Issue-K integration” bucket is factually wrong

The default runner reports all 16 skipped tests with the same message:
`Issue K: ode45-based integration path does not terminate here`. The contents
of that list contradict the message:

- `verify_step41_sat_antiwindup_loop` performs one controller evaluation and
  no trajectory integration at all. It belongs in the fast block.
- `verify_phase_b3_projected_convergence` uses the production projected-RK4
  path, not `ode45`; it is a known expensive production regression, not an
  Issue-K unknown.
- `verify_step23_single_auv_mb`, `verify_step24_3auv_mb`, and experiments
  0/1/2/3/5 use model-based or conventional controllers with `ode15s`; they
  contain no critic weights, so the stated critic-projection-boundary cause
  cannot explain them. The observed step-23 stall is useful evidence of a
  runtime problem, but not evidence for the blanket root-cause label.
- `verify_phase_b2_hybrid_behavioral_sanity` targets an already invalidated
  hybrid path and should be classified as legacy/invalidated rather than as a
  current unknown regression.

Split the suite into at least: fast deterministic, slow-but-valid production,
known-stalling legacy, and invalidated/deprecated. Record a truthful per-test
skip reason. Prefer artifact-based checks for the committed Phase-C result so
the 100 s scientific assertions can run quickly without repeating a 3-hour
simulation. The coverage guard is useful and should remain.

Until this classification and the stale oracles are corrected, `44 passed, 0
failed, 16 skipped` means only that the fast subset passed; it is not a green
full verification-suite result.

### [P1] Fig. 4 is a documented qualitative mismatch, not a “shape-only” reproduction

The bound `|Chat| <= delta_c*sqrt(15)` at the current assumed `delta_c=100` is
correct and proves that this configuration cannot reach the paper's `1e8`
scale. The negative `Chat` samples are also real approximation invalidity for
a non-negative cost-to-go; they are not introduced by the plotting code.

However, the rendered curves go strongly negative, oscillate, and then settle
to one common level, whereas the paper comparison recorded in the repository
is a monotone rise from zero to three distinct positive plateaus. Calling this
“shape only” still overstates the match. Label it as a **provisional diagnostic
showing qualitative and quantitative mismatch**.

Also narrow the causal wording. The current `delta_c` is a sufficient scale
obstruction, but the bound does not prove that changing `delta_c` would recover
the paper, nor does it exclude effects from the assumed reward weights, basis
normalization, reward-signal choice, or learning dynamics. Likewise,
projection thrashing is consistent with the invalid approximation but is not
established as its unique cause.

I do **not** recommend spending compute on a blind `delta_c` sweep up to
`O(1e8)`. Such a change alters the learned dynamics and invalidates the current
production configuration. First define a theory/parameter-identification plan
and the invariants/abort gates for any new experiment.

### [P2] Fig. 5 contains an unsupported longer-horizon extrapolation

Showing both the selected z-DOF basis activations and the six-component actor
network output is transparent, and the z-DOF choice is properly marked as an
assumption. But the caption says `Wa ... would reach [delta_a] on a longer
horizon`. The 100 s trace establishes only the observed drift/trend; it does
not establish that the trend persists until projection. Replace the prediction
with an observation, or quantify it with a stated fit and a separate
extrapolation caveat.

This figure may remain committed as a provisional diagnostic. Matching the
paper's axis by construction is not, by itself, evidence that the paper's
Fig. 5 trajectory has been reproduced.

### [P2] The printed opt-in invocation is not executable

`generate_all_paper_figures` accepts result and manifest **paths** and then
calls `load` on them, but the skip message tells the caller to use
`generate_all_paper_figures(res, man, true)`. Passing the loaded structs would
fail. Print a valid call, for example `generate_all_paper_figures([], [],
true)` for the defaults, or show explicit path strings.
