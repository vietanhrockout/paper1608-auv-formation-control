## Remaining findings

### [P1] Step 52 trusts a derived cache without binding it to the raw result

`verify_step52_performance_criteria` loads
`artifacts/phase-c/phase_c_analysis_t100.mat` for `t`/`E_chi` and independently loads
`artifacts/phase-c/phase_c_manifest_t100.mat` for actuator maxima. It never loads
`artifacts/phase-c/phase_c_result_t100.mat`, recomputes `E_chi`, or even compares the manifest
embedded inside `analysis` with the separately loaded manifest. Therefore a
stale or mismatched analysis/manifest pair can pass while saying nothing about
the committed raw trajectory.

This is especially important because the oracle is now the fast scientific
gate replacing a 3.3-hour simulation. Make the gate independent of the cached
summary:

- load the committed raw result and manifest;
- verify basic pairing invariants (`t_final`, stored sample count, time grid,
  run SHA/dirty state/config as applicable);
- recompute `E_chi` from `res.X` with the production formation-error definition;
- assert the 10 s, `[10,100]`, and final criteria on that recomputation;
- optionally compare the recomputed series to `artifacts/phase-c/phase_c_analysis_t100.mat` and
  fail if the cache is stale.

This is post-processing only and does **not** require rerunning Phase C.

### [P1] Two deferred-test reason strings are still contradicted by source

The requested per-test classification is not yet truthful in two cases:

1. `verify_step55_pt_validation` is labeled `slow-mb` / no critic, but it calls
   `sweep_initial_conditions(3)`, whose line 30 integrates
   `rhs_3auv_rl` with `ode15s` and packed actor/critic weights. It belongs in an
   RL/adaptive-solver class (or a separately named RL sweep class), not
   model-based/no-critic.
2. `verify_step51_exp_runner` is labeled `stalling-rl` because
   `run_all_experiments` supposedly includes the legacy `exp4_rl_pts_mc`
   `ode45` path. Current `run_all_experiments.m` lines 20–25 explicitly call
   `exp4_rl_pts_mc_projected`. This is a composite slow test containing the
   model-based experiments plus the valid projected-RK4 experiment; its current
   reason string describes code that no longer runs.

Correct both entries after following their current call chains. Do not infer a
root cause merely from their historical names.

### [P2] The runner header still contains the blanket claim R12 removed

`run_all_verifications.m` lines 21–35 still say that trajectory oracles invoke
`ode45`-based paths and that `ode45`, hybrid, and `ode15s` all stall near the
critic projection boundary. This directly contradicts the new classification
below it, including the model-based/no-critic and projected-RK4 classes.

Update the function contract/header and the `include_integration` description
to match the four-class design. Also rename the displayed “Algebra-level
oracles” block to something such as “Fast/no-simulation oracles”: step 52 is
artifact-based post-processing, not an algebra-level oracle.

### [P2] Step 52 no longer self-configures its MATLAB path

The master runner adds `genpath(project_root)`, so the committed suite log
passes. But unlike the other verification functions, step 52 itself no longer
adds the config path before calling `saturation_config()`. A direct call from a
clean MATLAB session can therefore fail solely because of caller path state.
Restore standalone path setup or avoid the hidden dependency.
