## Requested changes

### [P1] Narrow the claim that "Issue M/K is eliminated"

The new evidence proves zero projection/retraction events across the 1,000,000
steps of the **fixed-step projected-RK4** production run. It does not yet prove
that every behavior grouped under Issue K is eliminated.

The committed fast-suite output and `run_all_verifications.m` still classify
four deferred adaptive-solver/RL oracles as `stalling-rl` / "genuine Issue K":

- `verify_step44_numerical_stability`
- `verify_step49_exp4`
- `verify_step55_pt_validation`
- `verify_phase_b1_behavioral_sanity`

None was rerun to completion under the corrected `tau_act_saturated` default.
Either rerun and truthfully reclassify them, or narrow the HANDOFF and
IMPLEMENTATION_STATUS wording to: **the critic projection thrashing is
eliminated in the corrected projected-RK4 Phase-C run**. Do not convert this
single-integrator result into a blanket closure of the adaptive-solver issue.

### [P1] Reconcile the public/current scientific-status documents

The maintained documents currently disagree with the merged implementation:

- `README.md` still lists `tau_cmd` versus `tau_act` as unresolved and still
  gives the superseded approximately-200-minute runtime instead of 138.2 min.
- `paper1608/docs/EQUATION_MAPPING.md` marks Eq. (16) / Issue M unresolved.
- `paper1608/docs/assumptions_log.md` still calls feeding `tau_cmd` a VERIFIED
  implementation assumption.
- `paper1608/docs/IMPLEMENTATION_STATUS.md` says Issue M/K/N and the reward
  reading remain open immediately before its later RESOLVED section.
- The README calls physical Figs. 2, 3, 6, 7, 8, 9 "Accepted" by linking R11,
  but R11 reviewed the superseded `tau_cmd_raw` dataset. The regenerated
  figures need a fresh bounded review, or the status must explicitly state
  that R11 accepted the earlier dataset and the new render is not yet
  independently re-accepted.

Make one authoritative current-state statement and propagate it across these
entry points. Historical sections may remain, but they must be clearly marked
as superseded rather than read as the current configuration.

### [P2] Bind the supervisor decision and artifact mode into fast regression

There is still no fast oracle that pins the production default to
`tau_act_saturated`. `verify_step35b_critic_control_cost_signal` numerically
checks both candidate utilities but does not assert which one is the production
path. `verify_step52_performance_criteria` reads `params=res.params` from the
artifact and does not compare its reward mode against the current
`simulation_params()` default. A future configuration drift or legacy artifact
swap could therefore remain green.

Add fail-closed checks that:

1. assert the production default is `tau_act_saturated`;
2. assert the committed Phase-C artifact records that same mode; and
3. compare the artifact mode with the current production default.

Also make `scripts/validation/run_b3_tauact.m` assert or explicitly pass the
requested mode rather than merely printing the mutable default.

### [P2] Remove remaining stale source/test messages

- `rhs_3auv_rl.m` still comments that `tau_cmd_raw` is the default.
- `verify_step35b_critic_control_cost_signal.m` still prints
  `tau_cmd cost path verified`, although the PR description says this message
  was corrected.
- Several diagnostics still describe `tau_cmd_raw` as the unchanged current
  default.

These do not change the current numerical run, but they are misleading audit
evidence and should be corrected with the documentation pass.

### [P2] Refresh or supersede the public release

The only release/tag remains `v0.9.0` at `beeddd2`, before the supervisor's
Eq. (16) decision and before the corrected Phase-C dataset. Because the reward
choice changes the closed-loop dynamics, that release must not be mistaken for
the current production configuration. Publish a new release after the above
status corrections, or label `v0.9.0` explicitly as the legacy
`tau_cmd_raw` physical-state milestone.

## Scientific boundary retained

This review accepts the corrected input signal and the refreshed physical-state
production evidence. It does **not** promote the project to a full quantitative
paper reproduction:

- the literal 5 s reaching deadline remains missed (observed neighborhood entry
  is approximately 7.1–7.5 s);
- Fig. 4 remains invalid as a cost-to-go reconstruction because `Chat` is
  non-positive, has the wrong scale by roughly seven orders of magnitude, and
  has different per-AUV ordering;
- Figs. 4–5 remain provisional diagnostics; and
- the 14 deferred integration oracles are not known-passing.

No additional 100 s Phase-C rerun is requested for this review. The requested
work is truthful status reconciliation, regression binding, targeted
adaptive-solver reclassification/testing, and release hygiene.
